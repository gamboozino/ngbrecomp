# Working on this project

Notes for contributors and coding agents: how the project is laid out, how to build and test it, and
the rules that keep a test run from disturbing the machine it runs on.

## Layout

- `src/` — the hand-written part: start-up and paths (`main.c`, `install.c`, `port.h`), the settings
  (`launcher.c`, `pc_menu.c`, `ingame_menu.c`, `pause_tab.c`), input (`keyboard.c`, `bindings.c`,
  `menu_mouse.c`), game fixes and options (`cheats.c`, `movie_skip.c`, `costume_menu.c`, ...), the
  Direct3D renderer on Vulkan (`src/d3d`, see `docs/renderer.md`).
- `src/recomp/gen/` — the lifted game code, generated by `tools/pipeline.sh` from the player's disc.
  **Never commit it**, nor the game's data (`game_files/`, `disc/`, `*.xbe`, `*.afs`, saves, captures
  of the game's pictures). Only the functions taken out of it to be modified (`tools/take_function.py`,
  listed in `src/manual_functions.json`) are kept in the hand-written sources.
- `src/recomp/gen_trilogy/`, `src/recomp/gen_tomoe/` — the arcade Ninja Gaiden (`NinjaTrilogy.xbe`, and
  `NinjaTomoe.xbe` the Japanese build), generated by `tools/pipeline_trilogy.sh [tomoe]` (never commit
  them either); host `src/trilogy/main.c`, hand-over in both directions `src/launch.c`; their shared
  seeds `src/icall_targets_trilogy.json`.
- `src/manual_functions.json` — lifted functions replaced by hand-written ones (the generator skips
  them); `src/icall_targets.json` — indirect-call targets the analysis missed (`tools/feedback.sh`).
- `packaging/` — the AppImage (`appimage/build.sh`, in Docker) and the Windows zip
  (`windows/build.sh`, cross-compiled with llvm-mingw); shader seeds shipped with both.
- `docs/` — `TECHNICAL.md` (how everything works), `renderer.md`.
- `xboxrecomp/` — the recompiler and Xbox runtime: [xboxrecomp](https://github.com/sp00nznet/xboxrecomp)
  with this port's changes, kept here (see `xboxrecomp/UPSTREAM.md`); its third-party sources come
  from `xboxrecomp/third_party/fetch.sh`. `-DXBOXRECOMP_DIR=` builds against another copy.

## Building

```sh
xboxrecomp/third_party/fetch.sh         # once
tools/pipeline.sh /path/to/ngb.iso      # once, and after changing the analysis inputs
tools/pipeline_trilogy.sh               # the arcade (NinjaTrilogy); "tomoe" for NinjaTomoe
cmake -S . -B build/linux -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
ninja -C build/linux                    # build/linux/NinjaGaidenBlack (+ NinjaTrilogy, NinjaTomoe)
packaging/appimage/build.sh             # build/appimage/NinjaGaidenBlack-x86_64.AppImage
packaging/windows/build.sh              # build/windows-release/NinjaGaidenBlack-windows-x64.zip
```

The generated code is large: cap the memory of big builds (`systemd-run --user --scope -p
MemoryMax=14G ...`).

## Testing

Test runs must never touch the user's own data or desktop:

- **Never the real saves or settings** (`~/.local/share/NinjaGaidenBlack`, `~/.config/NinjaGaidenBlack`).
  Copy what you need into a scratch folder and point the game there: `NGB_SAVE_DIR`,
  `XDG_CONFIG_HOME`, `NGB_GAME_DIR`; `NGB_NO_SETTINGS=1` skips the settings screen.
- **No sound**: `SDL_AUDIODRIVER=dummy` and `NGB_AUDIO=0` (under Proton only the latter reaches the game).
  With `NGB_AUDIO=0` the mixer still runs on a timer, so `NGB_DSOUND_WAV=<file>` records what would play.
  For timing, record that way: SDL's dummy output pulls about 5% faster than 48 kHz (it sleeps in whole
  milliseconds), which leaves a game that streams by the video frame (the arcade) a frame short now and then.
- **No windows on the desktop**: run inside a headless gamescope, with `env -u WAYLAND_DISPLAY`:
  `gamescope --backend headless -W 1280 -H 720 -- ./run.sh`.
- **Kill only your own processes**, by PID (check `/proc/<pid>/environ` for your scratch paths) —
  never `pkill` a pattern.

Driving and watching a headless run:

- `RECOMP_PAD_LIVE=<file>`: append pad commands to the file (`a`, `b`, `x`, `y`, `start`, `back`,
  `white`, `black`, `lt`, `rt`, `up`/`down`/`left`/`right`, `lup:<ms>` and the other stick
  directions, `name:<ms>` to hold). It acts at the USB level, so code that reads the host's input
  (the recomp's own menu pages) does not see it — use `xdotool` on the gamescope's own X display
  (find it in the game's environment; never `:0`) for keys and the mouse.
- `RECOMP_PAD_HOST=<file>`: a virtual controller SDL takes for a real one, the only one opened while
  it is there (the machine's own pads are left out). Lines appended: `<button>[+<button>...][:<hold ms>]`
  (`a b x y lb rb lt rt start back ls rs up down left right`), 200 ms apart, or right after the previous
  one when the line starts with `&` (hold one, then add a second). Unlike `RECOMP_PAD_LIVE` it reaches
  the recomp's own pages and the button bindings; the log shows `PAD: title gets ...`, what the game
  is handed after the bindings, as it changes.
- `NV2A_CAPTURE=<prefix>` and `NV2A_CAPTURE_EVERY=<n>`: a PPM of the presented picture every n
  frames. Keep `render_scale` low in test settings, or the captures fill `/tmp`.
- `NV2A_FPS_LOG=1`: frame rate, and `[LAT]` presentation timing.
- `NV2A_PACE_LOG=1`: every 2 s, how the frames are paced (`[PACE]`): the vblank's lateness, the flip releases
  and stalls, the guest's naps polling the GPU, the software-method interrupts, why the PFIFO thread was idle
  (no commands, a flip, held at the Multithreaded Renderer's gate...), and with that renderer its hand-overs
  (batches, hand-over to drawn, the title's waits). The first place to look when frames are slow but no thread
  is busy.
- `NGB_D3D_STATS=1`: every 60 frames the draws by target, the render passes, and per frame the GPU's time
  (timestamps around each command buffer) and the render thread's waits for the GPU.
- `NGB_D3D_KICKOFF_KB=n`: Direct3D's kick-off size; 256 by default with the Multithreaded Renderer, 0 the
  title's 32 (src/d3d/d3d.c).
- On Android, `simpleperf` (the NDK's, pushed to `/data/local/tmp`) profiles the game (the APK is profileable):
  `record --app io.github.gamboozino.ngbrecomp -e cpu-clock --call-graph fp [--trace-offcpu]`, then
  `binary_cache_builder.py -lib <dir with build/android-release/build/libmain.so>` and `simpleperf report`.
  `--trace-offcpu` shows where threads wait; it needs `-e cpu-clock` given.
- F7, or `NGB_TRACE_FILE=<file>` (recording starts when the file appears): every draw of the next
  frames and a small picture of each, in `~/ngb-trace-<n>` (`HOME` decides where).
- `NGB_RENDERER=xemu`: xemu's hardware-accurate renderer instead of ours — the reference for "is this
  our bug or the game's".
- Vulkan's validation layer: `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation`,
  `VK_LAYER_LOG_FILENAME=<file>`, `VK_LAYER_DEBUG_ACTION=VK_DBG_LAYER_ACTION_LOG_MSG`. Run it when a bug
  shows on one vendor's GPUs only: AMD's driver tolerates things others do not. Add `NGB_D3D_NO_PREWARM=1`:
  with the renderer's prewarm thread making pipelines while the game thread records, the layer (1.4.363)
  crashes in its own command-buffer checks in most runs (in 0.9.25 too). `VK_LAYER_VALIDATE_SYNC=1` adds
  synchronization validation; set `VK_LAYER_DEBUG_ACTION` without `VK_LAYER_LOG_FILENAME` to have the
  messages in the game's unbuffered log, so the last ones before a crash are not lost. The headless gamescope's
  own WSI layer adds swapchain and dma-buf messages that are not ours. The SPIR-V cache
  (`$NV2A_SHADER_CACHE/d3d/spirv.bin`: an 8-byte `NGBD3DC1` header, then records of hash u64, word count
  u32, words) can be split and checked offline with `spirv-val`.
- At the title, the first Start can be ignored while it loads; on the main menu the cursor starts at
  Load Game when saves exist. The recomp's own pause pages (Settings, Exit) read the host's keyboard, not
  `RECOMP_PAD_LIVE`: a stray Start in play opens the pause menu and the pad cannot close it.
- The attract demo plays out a little differently on every run: compare captures by what they show
  (counts, colours over a region), not frame by frame against another run.
- `NGB_CHEATS=1000` (infinite health) keeps a scripted walk alive; `NGB_D3D_SHADERDUMP=<dir>` writes every
  shader made (file names match a trace's `shaders` field).
- `NGB_MODE_LOG=2` (2D-screen decisions per frame), `NGB_HUD_GROUP_TRACE=1` (HUD placement),
  `NGB_MOUSE_LOG=1`, `NGB_MOVIE_LOG=1`.
- `kill -USR1 <pid>`: the guest thread's backtrace and registers (not gdb: it swallows the
  single-steps the APU traps use). `RECOMP_COVER_SNAP=<prefix>` plus `kill -USR2`: which lifted
  functions ran between two signals.
- Windows builds under Proton: `umu-run` with a scratch `WINEPREFIX` and `PROTONPATH` set to the
  full path of a Proton install; settings then live in the prefix's `AppData/Roaming`.

## Conventions

- Match the surrounding code: comments say why, in plain sentences; names and idioms as nearby.
- A behaviour change gets checked in a headless run — measured (positions, timings, logs), not
  assumed — at the aspect ratios it touches (4:3, 16:9, 16:10, 21:9, 32:9).
- Commits are small and describe the change; no build output, captures or game data in them.
- Shell scripts that loop over word lists should run under bash (`zsh` does not split `$var`), and
  a `pgrep -f` pattern matches its own command line.
